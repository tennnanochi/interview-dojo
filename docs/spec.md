## 概要と目的

Claude上にある3つの練習アプリ(フェルミ暗記帳・フェルミ道場・ケース面接道場)を、**URLを開くだけで使える1つのWebアプリ**にまとめる。学習履歴はアカウントに保存し、スマホとPCのどちらで開いても同じ状態にする。

- **なぜClaudeの外に出すか**: スマホで通勤中に開きたい。ホーム画面に置けて、ログインやチャットを経由しないほうが、練習の開始が速い。
- **なぜ統合するか**: 3つは「数字を覚える→型で解く→対話で仕上げる」の一連の学習。履歴と暗記データを共有すると、ケース道場の参照パネルに暗記帳の数字をそのまま出す、といった連携ができる。
- **成功の基準**: スマホで開いて3秒以内に暗記帳の1問目が出る。別端末で「覚えた」にした項目が、もう一方でも覚えた状態で表示される。

既存アプリはそのまま残し、新アプリが安定したら移行する。

## 利用シーンとユーザー

利用者は自分ひとり。公開はしないが、将来少人数に共有できる構造にしておく。

| シーン | 端末 | 時間 | 使う機能 |
|---|---|---|---|
| 通勤・スキマ時間 | スマホ | 1〜5分 | 暗記帳(片手で一問一答、スワイプ) |
| 昼休み・移動中 | スマホ | 10〜15分 | フェルミ道場(1問を段階ごとに選択式) |
| 家での本番練習 | PC | 30〜60分 | ケース道場(タイマー、メモ、講評) |
| 面接前の見直し | どちらでも | 5分 | 未暗記だけ表示、苦手な問題の復習 |

## 機能要件

MVPは暗記帳と同期。フェルミ道場とケース道場は、既存アプリの機能を移植してから広げる。

### 暗記帳(単語帳)

| 機能 | 内容 | 優先度 |
|---|---|---|
| カード表示 | 表=項目(例:就業者数)、裏=数値+メモ(実数、出典)。タップでめくる | MVP1 |
| 自己採点 | めくった後に「覚えた/あやふや/忘れた」の3択。スワイプでも操作可 | MVP1 |
| 出題モード | 全部/未暗記だけ/復習期限が来たもの(間隔反復)/カテゴリ指定 | MVP1 |
| 一覧モード | 今の暗記帳と同じ表形式。数値を隠す/表示を切り替え | MVP1 |
| 進捗 | 覚えた数/全体、カテゴリ別の制覇率、連続学習日数 | MVP1 |
| 逆方向の出題 | 数値から項目を当てる(例:「2km²」→「徒歩10分圏」) | 次期 |
| 数値入力で採点 | 数値を入力して、±30%以内なら正解とする | 次期 |

### フェルミ道場

| 機能 | 内容 | 優先度 |
|---|---|---|
| 段階式の演習 | 既存の「スコープ→幅出し→3段分解→セグメント」を移植。各段階は選択式+自由記述 | MVP2 |
| 5ステップの型 | 前提・定義→アプローチ(2案→絞る)→モデル化→計算→検証の順で記入欄を出す | MVP2 |
| 模範解答 | 式、採用した式と不採用の理由、チェック項目。既存の問題を引き継ぐ | MVP2 |
| 計算ツール | 魔法の式(○分圏の面積)、簡易ピラミッド、電卓を横に置く | 次期 |

### ケース面接道場

| 機能 | 内容 | 優先度 |
|---|---|---|
| お題バンク | 既存150問。フェルミ/ケース/複合で絞り込み、過去のスコア表示 | MVP2 |
| 練習画面 | タイマー、メモ用紙、電卓、参照パネル(暗記帳の数字を共有) | MVP2 |
| 自己採点 | チェックリスト(前提確認、+10%と+50%の施策、単価低下の相殺など)で採点 | MVP2 |
| AI面接官・講評 | 回答を送ると深掘り質問と講評が返る(「AI講評の扱い」参照) | 次期 |
| 音声入力 | 話した内容を文字起こしして回答欄に入れる | 次期 |

### 共通

- ログインと端末間の履歴同期。**最初はメールのログインリンク(Magic Link)で始め、動いたらGoogleログインを追加する**
- ホーム画面に追加できる(PWA)。電波がない場所でも暗記帳は動き、つながったら同期する
- ダークモード対応
- データの書き出し(JSON)。万一のときのバックアップ用

## 画面構成

画面下に「ホーム/暗記帳/フェルミ/ケース/記録」の5つのタブを置き、どの練習もホームから2タップ以内で始められるようにする。

```
ホーム(今日の復習枚数・続きから再開)
├─ 暗記帳 → カード出題(めくって3段階で採点) → 結果(覚えた数・次の復習日)
│        └ 一覧(数値を隠して見返す)
├─ フェルミ道場(問題一覧) → 段階式の演習(5ステップで記入) → 模範解答(チェックで自己採点)
├─ ケース道場(お題バンク) → 練習画面(タイマー・メモ・電卓) → 振り返り(自己採点・AI講評)
└─ 記録(進捗・連続日数・設定)
```

見た目は画面モック(ホーム、カード出題、一覧、フェルミ演習、ケース練習の5画面)を参照。配色は既存アプリに合わせた緑系(アクセント #1f5f4a、背景 #eef1ee)、フォントは Zen Kaku Gothic New と JetBrains Mono(数字)。

## データ設計と同期

問題データはGitHubのJSONファイルで管理し、学習履歴だけをDBに保存する。問題の追加はファイルを更新してpushするだけで、DBは触らない。

### 問題データ(リポジトリ内の data/)

| ファイル | 主な項目 | 件数 |
|---|---|---|
| cards.json(暗記帳) | id、legacyId、version、group、section、item(項目)、value(暗記値)、note(実数・メモ)、source(video/added/confirmed)、updated | 273件 |
| fermi.json(フェルミ道場) | types(試算方法12種の説明)、questions(id、title、genre、want/who/stockFlow、scope、approaches、adopted、why、breakdown[3段]、segment、check、bookNo、origin) | 186問 |
| cases.json(ケース道場) | levels、typeNames、questions(id、type=fermi/case/combo、level、industry、text) | 150問 |

- **idは変えない**: 履歴はidで紐づくので、数値や文言を直してもidはそのままにする。旧暗記帳は「区分|項目名」をidにしていた(cards.json の legacyId)。新アプリでは card-0001 形式の専用idを使う。
- **数値を直したら復習し直す**: カードに version を持たせ、version が上がったら「覚えた」を外して復習対象に戻す。
- 新しいカードは末尾の番号の続きでidを振る(欠番は再利用しない)。

### 学習履歴(Supabase、ユーザーごと)

テーブル定義は `supabase/schema.sql`(Supabase に適用済み)。

| テーブル | 主な項目 |
|---|---|
| card_states | user_id、card_id、status(new/learning/known)、due_on(次の復習日)、streak(正解連続数)、card_version、updated_at |
| reviews | user_id、card_id、grade(good/unsure/forgot)、reviewed_at(進捗グラフ用のログ) |
| attempts | user_id、kind(fermi/case)、question_id、answer、self_score、ai_feedback、duration_sec、created_at |

どのテーブルも行単位のアクセス制御(RLS)で、本人の行しか読み書きできない。

### 同期の仕組み

1. 操作はまず端末内(IndexedDB)に保存し、画面はすぐに反応する。
2. 通信できるときに、変更分をDBへ送る。圏外ではためておき、つながったらまとめて送る。
3. 起動時と画面を開き直したときに、DBから最新の状態を取り込む。
4. 同じカードを両端末で変えたときは、**updated_at が新しいほうを採用**する。自分ひとりの利用なので、この単純なルールで十分。
5. 初回ログイン時に、旧暗記帳アプリの「覚えた」を読み込む移行機能をつける(旧アプリのidは legacyId で対応づける)。

### 復習の間隔(間隔反復)

「覚えた」は1日→3日→7日→14日→30日と間隔を広げ、「忘れた」は翌日に戻す。「あやふや」は間隔を変えない。30日を超えて正解したら「定着」として一覧で別色にする。

## 技術構成とホスティング

GitHubに入れたコードをVercelが配信し、ログインと学習履歴はSupabaseに置く。どれも個人利用なら無料枠で始められる構成にする。

```
GitHub(非公開:コード+問題JSON) --push で自動デプロイ--> Vercel(静的ホスティング) --配信--> スマホ・PC(PWA、IndexedDB)
スマホ・PC <--ログイン・履歴の同期--> Supabase(Auth + Postgres)
Supabase --(次期)--> Claude API(サーバー関数経由で講評)
```

| 役割 | 採用案 | 理由 |
|---|---|---|
| 画面 | Vite+React+TypeScript(PWA) | Claude Codeで作りやすく、ホーム画面に置ける |
| 配信 | Vercel | pushすると自動で公開される |
| ログイン・履歴 | Supabase | ログインと、本人しか読めない設定が標準でできる |
| 端末内の保存 | IndexedDB | 圏外でも動かし、つながったら同期する |
| AI講評(次期) | Claude APIをサーバー関数経由で呼ぶ | APIキーをブラウザに出さない |

## AI講評の扱い

Claudeの外で動かすと、AI講評にはAnthropicのAPIキーが必要になり、使った分だけ課金される。そのため**MVPではAI講評を入れず、自己採点と模範解答で回す**。

| 段階 | やり方 | コスト |
|---|---|---|
| 1. AIなし(MVP) | チェックリストで自己採点し、模範解答と見比べる | 0円 |
| 2. Claudeに渡す | 回答を「講評用の指示文+お題+回答」の形でコピーし、Claudeのチャットに貼るボタン | 0円(Proの範囲内) |
| 3. APIで直接講評 | サーバー側の関数からClaude APIを呼ぶ。キーはサーバーにだけ置く | 従量課金 |

- 段階2の指示文には、講評の型(フェルミの5ステップ、良かった点・計算ミス・論理ミス・改善した骨子、独自の視点)を固定で入れる。
- 段階3に進むなら、1日あたりの利用上限を設け、ログイン必須にする。導入前に公式の料金表で試算する。

## 非機能要件

| 項目 | 要件 |
|---|---|
| 速さ | スマホの回線でも、開いて3秒以内に暗記帳が使える。2回目以降は端末のキャッシュから即表示 |
| オフライン | 暗記帳とフェルミ道場は圏外でも動く。AI講評だけ通信が必要 |
| スマホ操作 | 片手で親指が届く下半分にボタンを置く。タップ領域は44px以上 |
| セキュリティ | 履歴は本人しか読めない(RLS)。秘密の鍵(service_role key、APIキー)はリポジトリに入れない |
| 公開範囲 | URLを知っていれば画面は開けるが、履歴の保存にはログインが必要。教材由来の問題を含むので、リポジトリは非公開 |
| 運用費 | AI講評を入れるまでは、ホスティングとDBとも無料枠の範囲で運用する |
| 保守 | 問題の追加・修正はJSONを編集してpushすれば自動で反映される |

## 開発の進め方とマイルストーン

1. **準備(完了)**: リポジトリ、問題データ(data/)、Supabaseのテーブルとログイン設定。
2. **MVP1:暗記帳**: カード表示・自己採点・一覧・進捗、ログインと同期、Vercelで公開。完了条件は「スマホで覚えたカードが、PCでも覚えたになっている」。
3. **MVP2:フェルミ道場とケース道場**: 問題データを使い、自己採点までの流れを移植する。参照パネルを暗記帳のデータと共通化する。
4. **次期**: 間隔反復の調整、逆方向の出題、Claudeに渡すボタン、音声入力、必要になったらAPIでのAI講評、Googleログイン。
